# Worktree Artifact Safety & Orchestrator Fail-Fast — Design

> Resolves [#31](https://github.com/gustavo-meilus/superpipelines/issues/31): sub-agent git worktree isolation causes silent artifact data loss and massive orchestrator token bleed on gitignored paths.

## Problem

When a pipeline step runs with `isolation: worktree` and writes its artifact to the canonical `<scope-root>/superpipelines/temp/` tree (which is gitignored under `local` scope), the artifact is destroyed during worktree teardown. The orchestrator's copy-back step then hits `cannot stat`, concludes the subagent "ghosted," and re-runs the entire subagent protocol **inline in the root session** — flooding the main context window with raw fetch/scrape payloads (catastrophic token bleed).

### Root cause (verified against official docs)

Per the Claude Code sub-agents documentation:

- **`isolation: worktree`** runs the subagent in a temporary git worktree, "branched by default from your **default branch** rather than the parent session's `HEAD`. The worktree is **automatically cleaned up if the subagent makes no changes**."
- **Without isolation**, "a subagent starts in the main conversation's current working directory" — i.e. the shared host workspace filesystem.
- **`acceptEdits`** auto-accepts edits only "for paths in the working directory or `additionalDirectories`."
- Subagent completion "results return to your main conversation" as a **summary** — the parent does not automatically receive files.

The true mechanism is **CC's no-change auto-teardown**, not git ignoring files: a pure data-retrieval/generation agent that writes only to a gitignored path makes **zero tracked changes**, so Claude Code automatically removes its worktree — taking the only copy of the artifact with it. The plugin's manual `cp` from the worktree path was always fragile; CC merges only *tracked* worktree changes back, never gitignored temp files.

## Goals

1. **Artifact retention** — artifacts generated by isolated steps survive teardown.
2. **Graceful failure** — a subagent reporting `DONE` with a missing declared artifact is a hard failure surfaced to the user, never a trigger for inline re-execution.
3. **Audit guardrail** — `pipeline-auditor` detects the worktree-on-gitignored-path flaw at create/mutation time so new pipelines cannot ship it.

## Non-goals

- No automated cross-platform parity gate (remains `PARITY_TESTING: MANUAL_PHASE1`).
- No change to the worktree safety protocol for legitimately code-modifying steps beyond artifact-path handling.

## Design

Four coordinated changes. **B is the primary fix**; A is the narrower code-modifying case; C and D close the symptom and guardrail.

| # | Change | File(s) | Fixes |
|---|--------|---------|-------|
| B | **`isolation: none` for data/artifact-only agents** (primary) | agent-frontmatter-schema, `creating-a-pipeline` Phase 4, `sk-pipeline-patterns`, parity-test examples | Eliminates the data-loss class entirely |
| A | **Host-anchored artifact paths + `additionalDirectories`** | `sk-pipeline-paths`, dispatch-protocols, `running-a-pipeline` | Code-modifying worktree steps that also emit artifacts |
| C | **Runner fail-fast (no inline fallback)** | `running-a-pipeline`, `pipeline-runner-references/escalation.md` | Token bleed |
| D | **Auditor detection rule** | `pipeline-auditor-references/severity-classification.md`, auditor checklist | Owner's comment — prevents new flawed pipelines |

### Component B — `isolation: none` for data/artifact-only agents (primary)

Pure data-retrieval/generation agents (read sources, fetch, write a coordination artifact, modify **no tracked code**) MUST NOT use `isolation: worktree`. Without isolation they run in the parent's cwd (the host workspace), write artifacts to the shared host filesystem, and there is no worktree teardown to destroy anything and no copy-back to fail.

- **Agent frontmatter schema** (`pipeline-architect-references/agent-frontmatter-schema.md`): document `isolation: none` as an explicit value alongside `worktree`/omit. Field-rules note: *"`worktree` only for steps that modify tracked code under Patterns 2/3/5. Data-retrieval/generation agents (no tracked-code writes) MUST use `none` — a worktree with no tracked changes is auto-cleaned by Claude Code, destroying any gitignored artifact it produced."*
- **Architect (`creating-a-pipeline` Phase 4)**: when assigning isolation, classify each step. Code-modifying → `worktree`; read-only / data-emitting → `none`.
- **`sk-pipeline-patterns`**: clarify that the Pattern 2/3/5 worktree mandate applies to **code-writer isolation**, not to data/coordination steps within those patterns.
- **parity-test example pipelines**: the reader/analyzer/reporter/summarizer agents are the reference case — set `isolation: none` on each as the canonical example of correct data-agent configuration.

### Component A — Host-anchored artifact paths + additional directories

For steps that **do** modify tracked code under Patterns 2/3/5 but also emit a coordination artifact, the artifact tree must anchor on the **main worktree root**, never the linked worktree.

- **`sk-pipeline-paths`** — add `RESOLVE_HOST_WORKSPACE()`:
  ```
  RESOLVE_HOST_WORKSPACE():
    common = `git rev-parse --path-format=absolute --git-common-dir`   # <host>/.git
    if success: return dirname(common)        # strip trailing /.git → host root
    else: return cwd                          # not a git repo → cwd
  ```
  New invariant: the `superpipelines/temp/{P}/{runId}/` artifact + state tree ALWAYS resolves under the host workspace root. Code edits stay isolated in the worktree; coordination artifacts land on the host.
- **Dispatch** (`pipeline-runner-references/dispatch-protocols.md`, Common dispatch shape): inject the **absolute host temp path** into the worker prompt as its output path. Worker writes there directly. The post-DONE `cp` copy-back step is **deleted** — removing the `cannot stat` failure entirely.
- **`additionalDirectories` (Gap 1)**: writing to the host scope-root from inside a worktree is *outside the working directory*, so `acceptEdits` will not auto-accept it (it prompts or fails). For any worktree step that writes to the host temp path, `running-a-pipeline` MUST register the host scope-root in the subagent's `additionalDirectories` at dispatch. Without this the fix re-introduces a (different) failure.
- **Default-branch note (Gap 2)**: document that a worktree branches from the **default branch**, not the parent `HEAD`, so a worktree subagent does not see the parent's uncommitted work. This is by-design for code isolation and an additional reason data agents gain nothing from worktrees.

### Component C — Runner fail-fast (no inline fallback)

- **`running-a-pipeline`**: codify that a subagent reporting `DONE` whose declared output artifact is **missing** is a hard failure. The orchestrator surfaces a `BLOCKED`-style escalation naming the missing path and the producing step. It MUST NOT execute the subagent's protocol in the root session under any circumstance.
- **`pipeline-runner-references/escalation.md`**: add explicit anti-pattern — *"Inline fallback on a missing artifact = token bleed; forbidden. Missing artifact after DONE → escalate, never re-run inline."*

### Component D — Auditor detection rule

- **`severity-classification.md`** — new **SEV-0** example: *"Step declares `isolation: worktree` and its declared output path resolves under a gitignored directory without host-anchoring (silent data loss on no-change worktree teardown)."* (SEV-0 per the table's existing "silent data loss" definition.)
- New **SEV-1** example: *"Pure data agent (no tracked-code writes) carrying `isolation: worktree` unnecessarily — auto-teardown risk + wasted worktree overhead."*
- **Auditor checklist**: add a *worktree-artifact-safety* criterion so `/audit-steps` and the post-mutation auto-audit (after new/update/delete-step) flag both cases with cited evidence.

## Data flow (after fix)

**Data agent (Component B):** orchestrator dispatches with `isolation: none` → agent runs in host cwd → writes artifact to `<host>/.claude/superpipelines/temp/{P}/{runId}/…` → returns DONE summary → orchestrator reads artifact from the shared host path. No worktree, no copy-back, no teardown.

**Code-modifying worktree agent (Component A):** orchestrator resolves host temp path, registers it in `additionalDirectories`, dispatches with `isolation: worktree` + injected absolute artifact path → agent edits tracked code in worktree (merged back by CC) AND writes artifact to host temp path → returns DONE → orchestrator reads artifact from host. No copy-back.

**Failure path (Component C):** any DONE with missing declared artifact → escalate, surface missing path, halt. Never inline.

## Testing / validation

No automated framework (CI validates JSON manifests + required files only); validation is manual per `PARITY_TESTING: MANUAL_PHASE1`:

1. Dry-run a Pattern 2/3/5 pipeline with a worktree code-writer that emits an artifact; confirm the artifact persists on the host after teardown and no copy-back runs.
2. Dry-run a data-agent pipeline (`isolation: none`); confirm artifact lands on host with no worktree created.
3. Run `/audit-steps` against a deliberately-flawed step (`isolation: worktree` + gitignored output, no host-anchor); confirm SEV-0 fires with cited evidence; confirm SEV-1 fires for an unnecessary-worktree data agent.
4. Self-review the four edited skills via `/audit-steps` for authoring-rule compliance (≤500 lines, third-person voice, ToC on references >100 lines).
